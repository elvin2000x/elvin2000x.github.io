Claude Code

Kept current · updated July 2026

Every code block from Ch 9 · Claude Code, in one place you can copy from. Model IDs and prices are current as of writing; live values are on the Stack page.

SNIPPET 1Here's what a hook configuration looks like in .claude/settings.json:

json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "python C:/Users/elvin/scripts/log_file_ops.py --event post_edit --file \"${tool_input.file_path}\""
          }
        ]
      }
    ],
    "Stop": [
      {
        "matcher": ".*",
        "hooks": [
          {
            "type": "command",
            "command": "python C:/Users/elvin/scripts/notify_telegram.py --msg \"Claude Code session complete.\""
          }
        ]
      }
    ]
  }
}

SNIPPET 2/standup, stored as .claude/commands/standup.md:

markdown
Read SESSION_STATUS.md and CLAUDE.md. Then:
1. List everything currently BLOCKED with what action is needed
2. List everything currently RUNNING automatically  
3. List what's READY TO BUILD right now (unblocked)
4. Note anything that changed since the last session log entry

Format as tight bullets per project. No prose.
Keep it under 30 lines. Be direct.

SNIPPET 3/checkpoint, stored as .claude/commands/checkpoint.md:

markdown
Update SESSION_STATUS.md to capture current state:
- Move completed items from this session to the session log with today's date
- Update the BLOCKED list: remove anything resolved, add anything newly stuck
- Update RUNNING list: note any changes to automated systems
- Update READY TO BUILD: reprioritize based on what just changed
- Add any new credentials, file paths, or key decisions to CLAUDE.md if they're permanent

Save the file. Confirm "Checkpoint saved." with a one-line summary of what changed.

SNIPPET 4/deploy, stored as .claude/commands/deploy.md (adapt to your stack):

markdown
Run the deployment checklist for the VPS:
1. Check that all modified files are committed in git
2. SSH into the server using the deploy key
3. Pull latest from main
4. Restart any affected services (check which based on what files changed)
5. Hit the stats endpoint to confirm it responds
6. Report: what deployed, what restarted, any errors

Do not proceed past step 3 without confirming git status is clean.

SNIPPET 5The initial version of SESSION_STATUS.md doesn't need to be comprehensive. Start with what's true right now:

markdown
# Session Status: [Today's Date]

## BLOCKED: needs action
- [project]: [what's stuck and what action unblocks it]

## RUNNING: automated
- [system]: [what it does, when it runs]

## READY TO BUILD
- [task]: [what it is, what done looks like]

## SESSION LOG
### [Today's Date]
- Created SESSION_STATUS.md
- Set up CLAUDE.md with initial context
