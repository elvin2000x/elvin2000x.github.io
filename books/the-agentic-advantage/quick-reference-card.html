Quick Reference Card

From The Agentic Advantage

Also online, free. This card is on the web, kept current, at elvinpeters.com/books/the-agentic-advantage/quick-reference-card.

One page to pin above the desk. Everything else in this book is the explanation behind these lines.

The loop. Trigger → act through a tool → observe the result → repeat → write what you learned to memory. Every agent is a variation on this.

The five tool categories. Information (learn), action (change things), execution (run things), memory (persist), orchestration (coordinate). Build at least one of each.

Model routing. Lightweight tier (Claude Haiku) for high-volume, low-complexity work. Balanced tier (Claude Sonnet) as the default. Frontier tier (Claude Opus) for the hard ten percent. Route deliberately.

Four ways to cut the bill. Cache the stable prefix. Cap the loop. Batch non-urgent work. Send cheap-first and escalate only when the cheap answer falls short.

Six tool-design rules. The description is the product. One tool, one action. Return structured data. Handle errors inside the tool. Log every call. Give an agent the three to five tools its job needs.

Five safety non-negotiables. Cap iterations so a confused agent cannot spin forever. Put a human in the loop before anything irreversible. Treat everything the agent reads as untrusted input. Keep keys out of prompts and logs. Enforce the load-bearing rules in code as well as in the prompt.

Five reliability habits. Watch the whole path the agent took, since a final answer can look right over a broken run. Assert on the response body rather than the status code. Make write actions idempotent so a retry is safe. Log every tool call for the 3am post-mortem. Keep a small golden set and run it on every change.

The one that matters most. Verify the parts that cannot be undone before you let the system run.
