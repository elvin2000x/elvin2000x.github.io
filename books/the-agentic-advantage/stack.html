The 2026 Operator Stack

Kept current · updated July 2026

Also online, free. This stack is on the web and kept current as tools and prices change, at elvinpeters.com/books/the-agentic-advantage/stack.

I built this appendix to hold everything with a short shelf life so the chapters could stay evergreen. Prices and product names in this field move every few months, so treat every figure here as a dated snapshot from the time of writing rather than a current quote, and verify the live numbers before you commit real budget (the companion Toolkit is the version I keep current). What actually lasts is not the price or even the product name. What lasts is the category each tool fills, because those categories are the true shape of an operator's stack. Read the tables for the shape first, and the specific names second.

Verify before you commit budget. Everything below was checked in mid-2026. Vendors reprice, get acquired, and rename tiers constantly, so confirm the current figure on the provider's own pricing page before you spend.

The organizing principle behind the whole stack is simple: buy the model, rent the infrastructure, own the orchestration.

Model APIs & SDKs (the model layer)

This is the engine. The SDK choice usually follows the model choice, and all three major SDKs speak MCP, so your tools stay portable across them. Model prices are quoted per one million tokens (input / output) and are the fastest-moving figures in this entire appendix.

Tool Category Rough cost (at time of writing) When to reach for it
Anthropic API + Claude Agent SDK Model API + agent harness Mid-tier ~$2–3 in / $10–15 out; light tier ~$1/$5; heavy tier ~$5/$25. Prompt caching cuts input ~90%, Batch API ~50% Default for agentic, coding, and tool-use work; the fastest path from a chat call to an autonomous loop
OpenAI Agents SDK + Responses API Model API + managed tools Flagship ~$5/$30; mid ~$2.50/$15; nano ~$0.20/$1.25; web-search tool billed separately You already live in the OpenAI ecosystem or want managed built-in tools (web search, file search, code interpreter)
Google ADK + Gemini Code-first agent framework + model ADK is free and open source; pay Gemini token rates plus platform compute; new-customer credit available You are on Google Cloud, need enterprise governance, or want a model-agnostic code-first framework

Note on model references throughout the book: I talk in tiers (light, mid, flagship) rather than pinning exact version ids, because the ids turn over faster than anything else here. When this table says "mid-tier," map it to whatever the current mid-tier model is at the time you read it.

Agentic coding tools (where most operators start)

This is Level 1 for almost everyone. These are the tools you drive to write the code that becomes your agents. Subscription tools bundle a token allowance; bring-your-own-key tools charge only for the tokens you burn.

Tool Category Rough cost (at time of writing) When to reach for it
Claude Code Terminal-first agentic coder Subscription tiers ~$20–200/mo, or API pay-per-token You want the strongest agentic-coding loop and a path to building your own agents on the same SDK
Cursor AI-native IDE (VS Code fork) Free tier; paid from ~$20/mo up to power tiers ~$200 You want an IDE-centric experience with best-in-class autocomplete
Windsurf AI IDE with agent Free; paid ~$20–200/mo on a quota model You prefer this agent UX; read the quota model rather than the headline price
Cline Open-source VS Code autonomous agent Tool is free; you pay tokens only (~$5–200+/mo by usage) You want transparency and direct control over model spend inside VS Code
Aider Open-source terminal pair-programmer Tool is free; tokens only You live in the terminal and want git-native, scriptable edits
GitHub Copilot (agent mode) Autonomous multi-file agent + inline completion Paid from ~$10/mo, higher tiers usage-metered You are deep in GitHub and VS Code and want agent mode alongside inline completion
Devin Async cloud "AI software engineer" From ~$20/mo You want a fire-and-forget cloud engineer for parallelizable, well-scoped tickets

Orchestration frameworks (when one model call is not enough)

Reach for these only when the model SDK's own built-in loop and subagents genuinely cannot hold the task. A framework is a cost to carry rather than a milestone to reach.

Tool Category Rough cost (at time of writing) When to reach for it
LangGraph Graph-based stateful orchestration Library free and open source; hosted platform ~$39/user/mo plus per-run metering You need durable, inspectable, cyclic workflows with fine-grained control and checkpoints
CrewAI Role-based multi-agent "crews" Library free and open source; enterprise is contact-sales You want a fast, high-level abstraction for role-playing agent teams
AutoGen / AG2 Conversational multi-agent Free and open source You want conversational multi-agent patterns or async, event-driven orchestration
LlamaIndex Data framework expanded to agents Library free and open source; hosted cloud is usage-based Your agent is retrieval-heavy and data connectors are the hard part
OpenAI Agents SDK Explicit handoffs and routing Free SDK; you pay model tokens You want routing and triage handoff apps living in the OpenAI ecosystem
Claude Agent SDK Orchestrator plus isolated subagents Free SDK; you pay model tokens You want the battle-tested Claude Code loop embedded in your own product or pipeline
Google ADK 2.0 Graph-first workflow engine Free and open source; pay platform compute You want enterprise, deterministic multi-agent flows with first-class human-in-the-loop

Rule of thumb: if the model SDK's built-in loop and subagents handle the job, add nothing. Add LangGraph for explicit state machines, CrewAI for role teams, and LlamaIndex when retrieval is the center of gravity.

No/low-code automation (fastest ROI for a solo operator)

Not everything needs to be code. For connecting apps and running visual flows, these earn their keep quickly. Watch the billing model closely, because it is where the real cost hides.

Tool Category Rough cost (at time of writing) When to reach for it
Make.com Visual scenario builder From ~$10/mo, priced per operation You want multi-step visual flows on a budget with strong operations-per-dollar
n8n Source-available workflow automation Self-host is free (server cost only); cloud from ~$20/mo You want to own it, run unlimited executions, or embed custom code nodes
Zapier Widest app catalog, per-task billing Free tier; paid from ~$20/mo, professional tiers ~$130+/mo Breadth of integrations matters more to you than per-task cost
Lindy AI-agent builder From ~$50/mo You want a persistent AI assistant instead of a static node graph
Gumloop No-code visual AI pipeline builder Free credits; paid from ~$37/mo You run repeatable AI-heavy pipelines like scraping, enrichment, or content
Relay.app Human-in-the-loop automation From ~$38/mo You want approvals and collaboration baked into automations

The billing model is the trap here. Zapier bills per task, meaning each individual action counts. n8n bills per execution, so a whole ten-step workflow counts as one. For a ten-step flow at ten thousand runs a month, self-hosted n8n can cut eighty to ninety percent off the Zapier bill. When a workflow needs real logic, secrets management, or git history, graduate it off the visual tool and onto code on a VPS.

Vector & memory DBs (giving agents recall)

A vector store is usually the read path for memory rather than the memory itself. Start on the cheapest option that fits your scale and only move up when ops or volume force it. Costs below are indicative at roughly ten million vectors.

Tool Category Rough cost (at time of writing) When to reach for it
pgvector Postgres extension Free (the Postgres you already run) You already run Postgres and want vectors, SQL, and transactions in one store; the default choice for most apps
Chroma Embedded / local OSS Free local; managed cloud tier Prototyping, local-first dev, and learning RAG with zero config
Qdrant OSS + managed Free tier; ~$30–65/mo cloud, no per-query fee Cost-sensitive production at scale with rich filtered search; best price-performance
Pinecone Managed serverless ~$70/mo at scale, consumption-based You want zero ops and cheap idle; watch query metering under heavy load
Weaviate OSS + managed Entry ~$25/mo; ~$135/mo at scale, less with quantization You need built-in hybrid search and modules and will tune quantization
Milvus OSS + managed Self-host or managed Billion-scale, GPU-accelerated, heavy workloads
mem0 Managed memory layer (not a DB) Free hobby tier; paid ~$19–249/mo You want persistent cross-session memory bolted onto an existing stack in a day
Letta / Zep / LangMem Agent memory runtime/layer (not a DB) OSS plus hosted tiers You want the memory logic (tiering, self-editing, temporal graph) on top of a store rather than a raw index

Default path: start on pgvector or Chroma, and move to Qdrant or Pinecone only when scale or operational load actually demands it. Remember that mem0, Letta, Zep, and LangMem provide the memory logic that sits on top of a database rather than being databases themselves.

Observability (you cannot debug what you cannot trace)

Add this the moment an agent runs unattended. Agent failures live in multi-step causal chains, so you need full-session trace capture rather than per-call logging.

Tool Category Rough cost (at time of writing) When to reach for it
Langfuse OSS tracing + evals Free self-host with no usage limits; paid cloud from ~$29/mo You want open-source flexibility, self-hosting, and the lowest entry cost; the default starting point
Arize Phoenix OTel-native tracing + eval library Fully open source, no cost; paid managed tier available You want OpenTelemetry-standard traces plus a strong open-source eval library
LangSmith Tracing + eval, tight with LangChain Free dev tier; paid ~$39/seat/mo plus trace metering You are already on the LangChain or LangGraph stack
Braintrust Eval-first observability Generous free tier; paid ~$249/mo Evaluation-driven development is core to how you ship
OpenTelemetry GenAI Vendor-neutral tracing standard Open standard, backend-agnostic You want multi-framework, future-proof instrumentation and to point any backend at the same data

Start with Langfuse (free and self-hostable) unless you are already on LangChain, in which case LangSmith is frictionless, or you are eval-obsessed, in which case Braintrust fits.

Hosting & always-on (where the agent actually lives)

An agent that only runs when you are watching is a demo. To make it a worker it has to live somewhere always-on. For a solo operator, a cheap VPS plus the operating system's own scheduler covers the overwhelming majority of always-on needs.

Tool Category Rough cost (at time of writing) When to reach for it
Hetzner Cloud Budget VPS Small box ~$9–10/mo with generous traffic Always-on agents and schedulers on a budget; best price-to-performance
DigitalOcean VPS plus managed services Basic droplet from ~$24/mo You want managed database and platform services around the box, US-centric
Serverless (Lambda / Cloud Run / Workers) Pay-per-invocation compute Usage-based with free tiers Bursty, event-driven agents you do not want to keep running
cron / Task Scheduler Built-in OS scheduler Free Simple "run this every N minutes" on a box you already own
Temporal Durable execution engine Self-host free; cloud from ~$100/mo Long-running, mission-critical workflows that must never lose state
Inngest Durable functions / step orchestration Free tier; paid from ~$75/mo Event-driven durable workflows without running Temporal yourself

For a solo operator, a small VPS plus cron or systemd covers roughly ninety percent of "always-on agent" needs for around ten dollars a month.

Search & scrape APIs (the agent's eyes on the web)

An agent that cannot see the live web is limited to what it already knows. These are the tools that give it current sight.

Tool Category Rough cost (at time of writing) When to reach for it
Brave Search API Independent web index Free tier; paid from ~$5/mo You want cheap, independent, privacy-first web results
Tavily Search purpose-built for agents ~$0.008/query, free tier You want a drop-in agent search with filtering and extraction
Exa Neural / semantic search From ~$0.001/result You want meaning-based discovery rather than keyword results
Firecrawl Scrape and crawl to clean markdown ~$99/mo at scale You are turning arbitrary sites into agent-ready markdown at volume
SerpAPI Faithful Google SERP scraping ~$50 per 5,000 queries You specifically need real Google SERP structure and fidelity

Default path: Tavily or Brave for agent search, Firecrawl for clean full-page extraction, Exa for semantic recall, and SerpAPI only when you genuinely need real Google SERP fidelity.

The Level 1 → 2 → 3 adoption ladder

The stack is a ladder you climb only as scale forces you up a rung, rather than a shopping list you buy all at once. Most operators stop climbing far earlier than they expect, and that is the correct outcome. Consider Dmitri, a fictional solo operator, as the reference climber.

Level 1: prompt and glue (Week 1, roughly $20–40/mo). One agentic-coding subscription plus a no-code automation tool for connecting apps. No hosting, no vector DB, no framework. Memory is files on disk, and observability is reading the terminal. Dmitri can automate real, revenue-touching work at this level, and most operators never need to leave it. Climb only when per-task automation costs start to bite, or when a workflow needs logic the no-code tool cannot express.

Level 2: own the loop (Month 1–2, roughly $30–80/mo). Dmitri moves the logic into code against a model API and agent SDK, and puts it on a cheap VPS run by cron or systemd. He adds pgvector or Chroma for memory and self-hosted Langfuse (free) for tracing, and self-hosts n8n if he still wants visual flows. Now he owns his automations, versions them in git, and pays only for tokens plus a cheap box. This is the sweet spot for a technical solo builder, and many stay here permanently.

Level 3: durable and multi-agent (only when justified, hundreds per month). Dmitri adds an orchestration framework (LangGraph for stateful control, CrewAI for role teams) only when a single loop genuinely cannot hold the complexity. He adds durable execution (Inngest, then Temporal) when losing mid-run state becomes expensive, and adds a managed memory layer, a managed vector DB at scale, and paid observability and evals once he is shipping to other people. He resists this level until a concrete pain, whether lost state, unmanageable branching, or multi-tenant scale, forces the move. Complexity is a cost to be justified rather than a milestone to be celebrated.

The through-line for all three rungs: add the next tool only when the pain of not having it is already real. The category tells you what slot a tool fills. Your own bottleneck tells you whether you need to fill it yet.
