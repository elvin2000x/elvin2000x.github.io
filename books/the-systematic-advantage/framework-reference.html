Framework Reference

From The Systematic Advantage

Every framework in the book on one page each, grouped by the stage of CRAFT it serves. Use this as the lookup you return to after the first read: what a framework is, what it is made of, and when to run it. The chapter that builds it is noted for when you want the full treatment.

The spine: CRAFT

Volume 2's operating cycle, and the successor to Volume 1's CLEAR. Where CLEAR taught you to direct a single session well, CRAFT builds the system in which good sessions happen reliably.

Configure

Architect's Mindset (Ch 1). The shift from working session by session to designing the system in which good sessions happen reliably. Volume 1's Director sets the vision inside a session; the Architect builds the environment so the vision no longer depends on remembering to set it. Run it whenever you notice yourself re-explaining the same context or re-solving the same problem.

AI Task Matrix (Ch 2). The framework for deciding what to hand to AI and how much to verify. Score a task on two axes: what the task is, and what an error would cost. The score tells you whether to delegate freely, delegate with a check, or keep it close. Run it at the start of any unfamiliar task before you decide how much to trust the output.

Workflow SOP (Ch 3). A documented, repeatable procedure for an AI-assisted workflow, written so a capable but non-expert colleague could run it. Four parts: the steps, the AI handoff points, the quality check, and who reviews before deployment. Build one the third time you run the same workflow by memory.

AI Operating System (Ch 4). The persistent infrastructure around your AI use: system instructions, context files, a prompt library, and workflow SOPs. The difference between a collection of prompts and an operating system is the difference between tools and infrastructure. Its supporting parts: - Memory Hardening Ladder: six rungs of durability, from naked chat that dies with the conversation, to saved prompts, standing instructions, context files, a working folder, and a self-maintaining system. Move a piece of context up a rung each time it proves it will recur. - The Effort Dial: match the model tier and reasoning effort to the task rather than defaulting to the most powerful setting. A configuration knob rather than a framework. - The Hardening Paradox: hardened memory repeats whatever it holds, including mistakes, so standing memory needs scheduled rereads. The harder the memory, the more expensive the error it carries. - The Re-Explanation Signal: the third time you type the same background paragraph into a fresh session, that paragraph is asking to become a file.

Refine

Professional Brief Model (Ch 5). The five-component brief that upgrades Volume 1's Role-Task-Constraint: objective, context, ranked constraints, output format, and success criteria. The brief is the durable asset; the prompt written from it is disposable. Build one for any output that matters or that you will produce more than once. - Constraint Hierarchy: rank a brief's constraints by whether their violation makes the output unusable (load-bearing) or merely imperfect (cosmetic), so the model spends effort where it matters.

Persistent Context (Ch 6). Standing memory that survives past a single session, moved out of the prompt and into the durable layer so a rule holds instead of drifting. Its failure mode is instruction drift: a rule held only in a prompt dilutes with every exchange until the model silently drops it. The cure is to move the rule up the hardening ladder.

Reasoning Prompts (Ch 7). A suite that makes the model pressure-test thinking rather than only produce it. Reach for the one that fits the risk: - Steelman Protocol: before finalizing a recommendation, have the model argue the strongest possible case against it, with no hedging and no restoring your confidence at the end. - Socratic prompting: get the output, then have the model argue against it as rigorously as it can. The gap between the two is where the real information lives. - Pre-Mortem: assume the plan has already failed, and ask for the specific mechanisms, so you get addressable pathways rather than abstract risk. - Assumption Audit: inventory what a plan depends on being true, rating each assumption's confidence and whether it has been tested. - Expert Panel: assemble multiple disciplinary perspectives and have them surface their disagreements before any synthesis, so you get the real tensions rather than a diplomatic average. - Red-Team Read: have the AI attack your finished deliverable the way your toughest stakeholder would, before that stakeholder sees it.

Apply

Project Handoff Protocol (Ch 8). The five-field artifact produced at a session's end and consumed at the next session's opening: project snapshot, decisions locked with reasoning, open threads, next-session objective, and critical context. It defeats context decay, the compound loss of working state between sessions. Its companions: - Decision Register: for long projects, a running record of every locked decision with its reasoning, so the handoff can point to it rather than recompress it. - Vocabulary Lock: a short glossary of the five to ten highest-weight working definitions for a project, so terms do not drift across sessions. - Fresh-Start Rule: if correcting prior outputs has replaced advancing the work, close the session and reopen fresh with the current handoff. You lose the contamination, never the content.

The Loop (Ch 9). The six-move method for a directed agentic session, run and rerun until it is reflex: Blindspot Pass (what have I not asked for), Interview Me (the agent completes the spec), Anchor with References, Prototype Wide (three or four different versions before refining one), Log the Deviations, Quiz Me (you own what you can explain).

Audience-First Brief (Ch 10). The Professional Brief rebuilt around a reader: recipient context, relationship dynamic, objective, tone register, and Voice Anchors. Communication is a briefing problem before it is a drafting problem. - Voice Anchors: two or three stable authorial patterns (how sentences open, whether asks hedge, the register between public and private) that make output read as authored. The one brief element no model can infer.

Analysis Brief (Ch 11). The Professional Brief specialized for analysis: the decision question, the audience, the input set with its limits and freshness, and the interpretation standard. - The Synthesis Mindset: after every synthesis output, ask "what does this mean, given what I know that this synthesis cannot know?" The residual act that stays yours. - The Stale Check: anything AI says about tools, prices, or versions carries an invisible expiry date. Two questions before a time-sensitive claim enters your work: how likely is this to be outdated, and how would I check.

Strategy Brief (Ch 12). The Analysis Brief plus a fifth element, the Assumption Register. - Assumption Register: what a recommendation presupposes, ranked by impact if wrong, so the presuppositions get tested rather than buried. - Assumption Risk Matrix: the register rated and sorted by likelihood-of-being-wrong against severity-if-wrong, critical assumptions first, so the audit tests only what would change the recommendation.

Leadership Voice Brief (Ch 13). The Audience-First Brief extended for leadership: the five communication elements plus relationship history, organizational stakes, development intent, and a maintenance protocol. - Voice Drift Check: a quarterly comparison of recent AI-assisted output against your Voice Anchor document, to catch the gradual homogenization toward AI's defaults.

Forward and Trust

Director's Due Diligence (Ch 14). The high-stakes verification standard that extends Volume 1's Two-Step Verification Method for outputs with professional, legal, financial, or reputational consequences. Three instruments: - Evidence-Weighted Output Model: review a high-stakes output claim by claim, sorting each into Tier 1 (verifiable facts, checked against a source), Tier 2 (reasoning, traced for logic), or Tier 3 (synthesis, weighed against judgment), and match effort to tier. - Reputational Audit: a six-question pre-send checklist, running from the most specific Tier 1 check to the broadest "am I prepared to put my name on this." - Accountability Map: a one-page written standard, one line per high-stakes output category, stating what you verify before that kind of output ships. Decided in advance so it holds under deadline pressure. - Calibrated trust and the Personal Error Ledger: track every correction in a high-stakes context for sixty days, and the pattern shows where AI is reliable in your specific domains and where it is not. - Second-Opinion Run: run the identical brief on a second model and diff the outputs. Agreement raises confidence; disagreement points straight at the claim to verify.

90-Day Team Adoption Plan (Ch 15). Three phases that move a team from broadcast to shared practice: Foundation (days 1–30), Expansion (31–60), Integration (61–90). - AI Champion: the person who builds a team's AI capability, distinct from being its AI expert. Four functions: translation, infrastructure building, practice modeling, and governance. The Champion succeeds by making themselves unnecessary for the basics. - Team shared infrastructure: the floor a team builds together: a shared prompt library that documents the missing context per entry, shared workflow SOPs, common system instructions, and a vocabulary document.

Quarterly Practice Audit (Ch 16). A ninety-day, forty-five-minute self-assessment that prevents the plateau: score the five practice dimensions, flag outdated or missing infrastructure, and set a focused plan on the two lowest dimensions. A design session rather than a grade. - Architecture Sprint: a ninety-day intensive for building a new infrastructure layer, with a defined scope, a defined timeline (one design week, eight build weeks, three integration weeks), and a defined exit state.
