Anatomy Sandbox for schools

Anatomy Sandbox: IT setup

Anatomy Sandbox is a 3D human body that runs in the browser. Students peel back skin, muscles, bones, nerves and organs. There are no accounts, no sign-in and no student data.

Your part takes about 5 minutes on Chromebooks, Group Policy or iPads (under 10 with Intune): paste one link into one policy. The app then reaches your devices on the policy's own schedule (usually minutes, up to a day; see the table at the end).

What you get from us (email elvin@elvinpeters.com): your campus ID, your campus link, the teacher PIN (for teachers, not students) and, if you need it, your campus's offline kit. Your campus link: https://elvinpeters.com/projects/anatomy-sandbox/?c=YOUR-CAMPUS-ID

What teachers and students see: the link opens in classroom mode. Reproductive and genital anatomy stay hidden. A teacher can show them by typing the campus PIN; that lasts until the page reloads, then it hides again. Five wrong PINs in a row lock the PIN box for 10 minutes.

Options A install it as an app that works offline after the first open and updates itself. Option B is one file with everything inside it.

Needs: a current Chrome, Edge, Safari or Firefox with WebGL 2 and hardware acceleration on (the default). If a policy turns off hardware acceleration (HardwareAccelerationModeEnabled = false) or WebGL, the app shows "This browser cannot show 3D".

Before you start (web filter, options A only): allow elvinpeters.com and api.elvinpeters.com. Nothing else: the app loads no third-party code, fonts or trackers. Option B needs nothing allowed.

A1. Chromebooks (Google Admin console)

  1. Go to admin.google.com > Devices > Chrome > Apps & extensions > Users & browsers.
  2. On the left, pick the student group (organizational unit). Google suggests a small test group first.
  3. Click the yellow + > Add by URL. Paste your campus link. Open it in a separate window. Click Save.
  4. Set Installation policy to Force install + pin to ChromeOS taskbar. Click Save.

A2. Windows, Edge or Chrome (Intune)

  1. In the Intune admin center: Devices > Manage devices > Configuration > Create > New policy.
  2. Platform Windows 10 and later, profile type Settings catalog, then Create. Name it "Anatomy Sandbox".
  3. Add settings, search force-installed Web Apps, and tick the Microsoft Edge one (and the Google Chrome one if students use Chrome).
  4. Turn it on and paste this, with your campus link: [{"url":"https://elvinpeters.com/projects/anatomy-sandbox/?c=YOUR-CAMPUS-ID","default_launch_container":"window","create_desktop_shortcut":true}]
  5. Assign it to the student device group. Create.

A3. Windows (Group Policy)

  1. Open the Group Policy Management Editor on the policy for student computers.
  2. Edge: Computer Configuration > Policies > Administrative Templates > Microsoft Edge > Configure list of force-installed Web Apps. Chrome: the same policy under Google > Google Chrome (needs the Chrome ADMX templates).
  3. Set it to Enabled and paste the same line as in A2, step 4. OK.

A4. iPads (Intune or Jamf)

  1. Intune: Apps > All apps > Create > iOS/iPadOS web clip. Jamf: a configuration profile with a Web Clip payload.
  2. Name "Anatomy Sandbox", URL = your campus link, Full screen = Yes. Leave "Require a managed browser" off.
  3. Assign it to the student iPads.

Test on one iPad first: Apple doesn't say whether a pushed web clip keeps its offline copy the way a home-screen app does.

B. Offline file (Windows labs with no internet)

Download anatomy-sandbox-school-kit.zip (about 28 MB; we send your classroom copy). Inside: Anatomy Sandbox.html, install.cmd, uninstall.cmd, a README and an icon. Your classroom copy checks the teacher PIN inside the file, so it never goes online.

  • Check and unblock it: we send a SHA-256 with each zip. In PowerShell, Get-FileHash anatomy-sandbox-school-kit.zip should match it. Then right-click the zip > Properties > tick Unblock > OK before you unzip, so Windows doesn't flag the files as downloaded. If AppLocker or WDAC blocks scripts, allow install.cmd by its hash or run it from your trusted share.
  • Try it: unzip and double-click Anatomy Sandbox.html. It opens in the default browser in about 10 seconds. Nothing needs to be running.
  • Intune (Win32 app): wrap the unzipped folder with IntuneWinAppUtil (setup file install.cmd). Install command install.cmd, uninstall command uninstall.cmd, install behaviour System. Detection rule: the file C:\Program Files\Anatomy Sandbox\Anatomy Sandbox.html exists.
  • SCCM / ConfigMgr: an Application with the same two commands and detection rule.
  • Group Policy: put the unzipped folder on a share every computer can read, then Computer Configuration > Policies > Windows Settings > Scripts > Startup > add install.cmd from that share.
  • One computer: right-click install.cmd > Run as administrator.

install.cmd is silent, takes about 2 seconds and needs no reboot. It adds a Start menu and a desktop shortcut for everyone.

Chromebooks: use A1. Many Chromebooks block opening files from disk.

Check it worked (1 minute, on one student device)

  1. Options A: the Anatomy Sandbox icon is on the shelf, taskbar or Start menu. Option B: it's in the Start menu and on the desktop.
  2. Open it. A 3D skeleton appears and the top reads "Classroom mode".
  3. Options A: wait for "Saved for offline use", turn Wi-Fi off, close and reopen it. It should still open.

After install

  • Open it once on school Wi-Fi. The first open saves the whole model (27 MB) for offline use. A small note says "Saved for offline use" when it's done.
  • Updates: options A update themselves the next time they open online. For option B we send a new file; run install.cmd again.
  • Computers that wipe themselves at sign-out (Chromebook "wipe user data on sign-out", guest mode, Deep Freeze, virtual desktops) download the 27 MB again each session. It still works, just slower to start. On Windows labs, option B avoids this.
  • Remove it: take the link out of the policy, or run uninstall.cmd.
  • If it says "This browser cannot show 3D": WebGL 2 is off. Turn hardware acceleration back on (Chrome and Edge: Settings > System > "Use graphics acceleration when available", or the HardwareAccelerationModeEnabled policy set to true), update the graphics driver, and check chrome://gpu or edge://gpu shows "WebGL2: Hardware accelerated". Old or remote virtual desktops without a GPU may not run it.
  • If the offline file opens blank: your browser policy may block files from disk (URLBlocklist with file://*). Allow file:///C:/Program%20Files/Anatomy%20Sandbox/* in URLAllowlist.

Privacy

No accounts, no sign-in, no cookies and no ad or analytics trackers. Nothing a student does is sent anywhere.

  • The online app loads everything from our own two addresses: the page, three.js and fonts from elvinpeters.com and the model from api.elvinpeters.com. It contacts no third party. On a campus link it asks our server once which campus the link belongs to, which also counts one open for that campus. When a teacher types the PIN, the PIN goes to our server to be checked.
  • What our server keeps: per campus, its name, the PIN as a one-way hash (never the PIN itself) and a daily count of opens. It writes no IP address anywhere and keeps no access log for these requests.
  • The offline file never goes online. The model, three.js and fonts are inside it, and a classroom copy checks the PIN inside the file.
